# Contributing to HackForge

## Branch naming

Use descriptive branch names:

- `feature/<name>`
- `fix/<name>`
- `docs/<name>`
- `refactor/<name>`

Examples:

- `feature/task-filter`
- `fix/task-validation`
- `docs/update-readme`

## Commits

Keep commits small and descriptive.

Good:

`Add task filtering`

Avoid:

`changes`
`final`
`stuff`

## Pull Requests

A Pull Request should explain:

- What changed
- Why it changed
- How it was tested

During training, every feature should normally go through a PR.
